# Foundry V14 Migration Checklist

Target: Foundry V14 with a minimum of 14.367. The manifest remains verified at 14.367; V14.368 is the latest stable release but has not been smoke-tested here. The current D&D5E release is 6.0.5, which requires Foundry 14.367. The newest available Foundry type snapshot is `14.366.0-beta.20261001000223`, one patch behind the retained verified build and two behind V14.368.

## Compatibility and Tooling

- [ ] Update `@league-of-foundry-developers/foundry-vtt-types` to a V14 version matching the chosen 14.367 target. The V13-to-V14 update is already in place: `package.json` and `yarn.lock` pin `14.366.0-beta.20261001000223`, the newest published version found on 2026-10-02. No 14.367 type package is published yet, so exact target alignment remains open. The deep `RoundData` import is gone, `updateCombat` uses the public hook type, and the D&D5E activity hook has a module-owned augmentation. Direct production type-checking reports 168 existing diagnostics; all 241 Jest tests, the build, and full lint pass. See [`package.json`](../package.json) and [`tsconfig.json`](../tsconfig.json).
- [x] Reconcile the module's Foundry compatibility range with the release target. The manifest declares minimum 14.367, verified 14.367, and maximum 14: V13 is excluded and later V14 builds remain installable. The verified value is the retained declaration; a live Foundry smoke result is still needed under Validation. `module.json` now explicitly declares `"type": "module"` and has a boolean `library` value, matching the V14 manifest fields; `package.json` separately declares ES module output. JSON parsing and field checks pass, but a Foundry runtime check is not available here. See [`module.json`](../module.json), the [V14 manifest API](https://foundryvtt.com/api/v14/interfaces/foundry.packages.types.ModuleManifestData.html), and the [package compatibility guidance](https://foundryvtt.com/article/package-management/).
- [x] Revisit the D&D5E compatibility declaration against the V14-compatible system release. The current D&D5E 6.0.5 release requires Foundry 14.367, matching this module's Foundry minimum. `module.json` already requires D&D5E 6.0.5; its D&D5E `verified` value remains unset until a live smoke test under Validation. The `dnd5e.postUseActivity` handler reads the Activity's `item` and `consumption.spellSlot` fields, and focused tests cover GM and player routing. See [`module.json`](../module.json), [`scripts/module.ts`](../scripts/module.ts), [`scripts/utils/Dnd5eActivity.test.ts`](../scripts/utils/Dnd5eActivity.test.ts), and the [D&D5E 6.0.5 manifest](https://raw.githubusercontent.com/foundryvtt/dnd5e/release-6.0.5/system.json).

## API and UI Refactors

- [x] Migrate the five settings panels from `FormApplication` to `ApplicationV2` with `HandlebarsApplicationMixin`. All five already inherit from `SettingsPanelBase`, which supplies the V2 form handler, 520 × 500 position, close-on-submit behavior, and shared template; each panel keeps its own title and explicit settings list. Focused tests cover menu registration, rendered fields, setting submissions, and write failures. A live V14 UI check remains under Validation. See [`scripts/panels/SettingsPanelBase.ts`](../scripts/panels/SettingsPanelBase.ts), [`scripts/panels/SettingsPanelBase.test.ts`](../scripts/panels/SettingsPanelBase.test.ts), and the [V14 ApplicationV2 API](https://foundryvtt.com/api/v14/classes/foundry.applications.api.ApplicationV2.html).
- [x] Verify the chat button integration against V14's chat rendering hooks. `scripts/module.ts` already listens to `renderChatMessageHTML`, whose HTML argument is an `HTMLElement`, and `ChatMessageHooks` binds a DOM click listener to the roll-table button. A hook-level test now covers newly rendered messages and a rerendered message; the helper tests cover duplicate binding, propagation, missing buttons, and failed rolls. A live V14 chat check remains under Validation. See [`scripts/module.ts`](../scripts/module.ts), [`scripts/module.test.ts`](../scripts/module.test.ts), and the [V14 renderChatMessageHTML hook API](https://foundryvtt.com/api/v14/functions/hookEvents.renderChatMessageHTML.html).
- [x] Migrate outgoing chat visibility from legacy roll modes to V14 Chat Message Visibility Modes. Player-triggered rolls use `public`, ordinary rolls use the client's registered V14 mode (including `gm`), and this module's GM-only settings retain their existing blind-to-sender behavior with `blind`. The custom-message example macro also uses `messageMode: "blind"`. Focused tests cover public, GM, and blind creation options and both macro messages; a live chat check remains under Validation. See [`scripts/Chat.ts`](../scripts/Chat.ts), [`scripts/Chat.test.ts`](../scripts/Chat.test.ts), [`scripts/custom-message-macro.test.ts`](../scripts/custom-message-macro.test.ts), [`scripts/macros/custom-message.js`](../scripts/macros/custom-message.js), and the [V14.355 visibility-mode notes](https://foundryvtt.com/releases/14.355).
- [ ] Audit the example macros for legacy Application V1 usage. In particular, migrate `new Dialog(...)` in `scripts/macros/dialog.js` to the V2 dialog API if V1 dialogs are no longer supported in the chosen compatibility range; test the macro pack in a clean V14 world. See [`scripts/macros/dialog.js`](../scripts/macros/dialog.js) and the [V14.349 ApplicationV2 notes](https://foundryvtt.com/releases/14.349/#release-highlights).

- [ ] Exercise the main workflows as both GM and player: spell activity detection, socket-based surge checks, roll-table output, whisper/blind visibility, combat-round checks, helper/settings dialogs, and every shipped example macro. ## Not Currently Indicated by This Codebase

The source scan found no use of MeasuredTemplate documents, TinyMCE, custom Active Effect schemas, or custom canvas/Scene Level APIs. Those prominent V14 changes do not appear to require a module-specific migration unless new code or user-facing content depends on them.
